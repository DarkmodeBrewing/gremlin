# M8 Handoff — v0.1 audit and release

## Status

Implementation is active on `feat/m8-v0.1-release`.

M8 closes the locked v0.1 specification through auditable source export,
credential rotation, authorization failure verification, database recovery
testing, operational documentation, and final release acceptance. It does not
add new product scope.

## Delivered so far

- Definition-of-Done audit mapped to repository and production evidence
- repeatable-read JSONL export of canonical interactions and events
- bounded keyset pagination for exports without loading all history into memory
- owner-only export file permissions and overwrite refusal
- atomic API-key rotation for active principals
- negative namespace tests including prefix-sibling boundaries
- production export, rotation, backup, restore, and release runbook

## Boundaries

- Source exports contain canonical interactions and events, not derived memory.
- The export format is versioned, but M8 does not add import tooling.
- Rotation supports one immediately active key per principal; grace periods and
  multi-key lifecycle management remain later operational work.
- Restore drills use a separate database and never overwrite production.
- Scheduled consolidation, event consolidation, memory lifecycle, and rebuild
  remain M9/M10 work.
