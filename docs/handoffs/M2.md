# M2 Handoff — Interaction Archive

## Status

M2 is implemented on `feat/m2-interaction-archive` and is ready for review.

## Delivered

- Registered principals authenticate with bearer API keys.
- Only SHA-256 API-key hashes are stored; generated keys are displayed once.
- Ingestion permission is resolved server-side from the authenticated principal.
- `POST /interactions` archives immutable source material with conversation ID, occurrence and storage timestamps, role, content, source provenance, and JSONB metadata.
- `GET /interactions/:id` returns a record only to the principal that submitted it and uses `404` for records owned by another principal.
- Request bodies are strict and cannot declare or override `sourcePrincipal`.
- Metadata has size and nesting limits and rejects credential-bearing key names recursively.
- Request and health failures return generic responses and avoid logging interaction content, credentials, SQL, or connection details.
- CI runs unit checks, build checks, the Compose smoke test, CodeQL, and interaction tests against real PostgreSQL 18 with pgvector.

## API contract

`POST /interactions` requires a principal with interaction-ingestion permission and accepts:

```json
{
  "conversationId": "018f4f7e-8c3a-7a61-8f55-3d6e7614f289",
  "timestamp": "2026-08-31T20:00:00Z",
  "role": "user",
  "content": "Raw interaction text",
  "metadata": {
    "provider": "example"
  }
}
```

The response adds `id`, `createdAt`, and the authenticated `sourcePrincipal`. `GET /interactions/:id` requires the same bearer credential and returns the stored representation.

Create a principal with:

```bash
pnpm principal:create client:gremlin-chat
```

Capture the generated key directly into a secret manager. It cannot be recovered from Gremlin after creation.

## Boundaries and follow-up

- Raw interactions have no application update or delete path. Do not edit migration `0002` after it has been applied; add a new migration instead.
- Retrieval is intentionally limited to the submitting principal. Broader source-read authorization belongs with a milestone that needs it.
- Key rotation, revocation operations, production secret provisioning, backup, restore, and source export remain future operational work.
- M2 does not include events, consolidation, embeddings, memory retrieval, MCP, or Gremlin Chat.

## M3 entry point

M3 should implement the smallest complete Gremlin Chat slice:

1. Add the basic chat UI and backend.
2. Integrate OpenRouter and stream assistant responses.
3. Authenticate the backend as `client:gremlin-chat` without exposing its API key to the browser.
4. Give each chat a stable conversation UUID and archive both user and assistant interactions through the M2 API.
5. Make either ingestion failure visible; never claim a message reached persistent history when storage failed.

Do not add consolidation or memory retrieval during M3; those begin in M4 and M5 respectively.
