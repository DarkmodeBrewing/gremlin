# M11 — Operations and observability, first slice

This first slice implements protected, read-only operator status and a recovery
runbook. It does not close the full directional M11 scope.

## Delivered for review

- `GET /admin/operations`: distinct-source backlog, source states, historical
  run totals, last successful run time and ten recent run summaries.
- Separate process-local HTTP observations for Prime's embedding and
  consolidation clients, including credential rejection and provider throttling.
- Existing `/health` remains independent of provider availability; polling
  operations status makes no model calls.
- Pre-authentication rate limiting, consolidator-only access, no-store responses
  and fixed provider error classifications without credentials or source content.
- [Database and credential recovery runbook](../runbooks/M11-operations-recovery.md).

## Verification — 2026-11-15

- Frozen-lockfile install, workspace typecheck and build: PASS.
- Unit suite: 45 tests, including seven provider-observation tests: PASS.
- PostgreSQL/pgvector integration suite: 44 tests, including five operations
  tests: PASS.
- New integration checks cover 401/403/429, empty state, real HTTP-provider
  failure classification through consolidation, unchanged database health,
  failed-attempt deduplication, recovered-source exclusion from backlog,
  last-success selection, and absence of credentials/source content in status.
- Disposable database, internal network, no production credentials or volumes;
  disposable database container and network removed after verification.

Provider HTTP status is transport evidence, not proof of valid model output or
completed consolidation. Observations reset on restart and may become stale;
run history remains database-backed. See the runbook for these limitations.

## Release and deployment boundary

The v0.2 release is tagged independently. PostgreSQL's merged restart policy
has been applied and verified running. The M11 application changes are not
merged or deployed by this handoff. After review and deployment, perform
read-only authenticated operations and health smoke checks. Do not inject
provider failures or truncate fixtures in production.

Durable provider telemetry, alert delivery, token/cost accounting, broader
principal tooling and disaster-recovery expansion remain subsequent M11 work.
