# M12 — Declarative client profiles, first slices

## M12.1: Contracts and offline validation

Versioned strict profiles for Gremlin Chat and OpenCode describe current
principal identity, activity, ingestion capabilities, read namespaces,
consolidation destination, connection/authentication environment references,
model selection, external execution/network expectations and repository context.
Offline validation includes comparison with the existing OpenCode adapter file.
CI runs it without database credentials or provider calls.

## M12.2: Read-only drift detection

The metadata checker compares those expectations with existing principal flags,
read grants and operator-supplied consolidation destinations. Exact and subtree
semantics are checked separately; a destination must be fully readable. Checks
use one repeatable-read, read-only PostgreSQL transaction and select no credential
hashes, canonical content or memories. Extra grants, elevated capabilities,
missing/inactive principals and unreadable/mismatched destinations are failures.

Profiles do not become an authority, provision users, change grants, resolve
secrets, execute clients, contact providers, orchestrate containers or access
Docker. No migration or HTTP endpoint is added. External model policies and
network requirements are declarations; runtime consumption/enforcement is deferred.

See [profile commands and schema boundary](../../profiles/README.md).

## Acceptance

- Offline validation: both checked-in profiles and existing adapter binding pass.
- Reject unknown/secret-value/command fields, incompatible MCP capabilities,
  duplicate identities and exact/subtree confusion without printing input values.
- Real PostgreSQL: metadata matches pass; permission/destination drift fails;
  a database role with only the required metadata-column SELECT grants can check
  profiles without credential-hash or write access. No state changes are made.
- Build/package: the operator CLI and reference files work in the Prime image.
- DM01: run the checker with destinations read from the actual Prime container,
  using protected database credentials. Record only the redacted result; do not
  deploy, reconfigure or grant permissions to make the check pass.

This is the first bounded M12 delivery, not full milestone closure. The next
slice can consume validated declarations in one concrete adapter after review;
there is no automatic execution or permission synchronization implied here.
