# M7 Handoff — Cross-client proof

## Status

Implementation is in progress on `feat/m7-cross-client-proof`.

The repository-side OpenCode integration and production acceptance runbook are
implemented. The actual cross-client production proof is still required before
M7 can be marked complete.

## Objective

Demonstrate that a fact introduced through Gremlin Chat / Model A can be
archived, consolidated into authorized derived memory, retrieved by a fresh
OpenCode / Model B session through MCP, and used to answer correctly without
giving Client B the original conversation.

## Delivered so far

- a dedicated OpenCode remote-MCP configuration under
  `clients/opencode/opencode.json`
- environment substitution for the MCP URL and Bearer credential
- OAuth auto-detection disabled for Gremlin's v0.1 API-key authentication
- OpenCode session sharing disabled
- explicit approval required for Gremlin MCP tools
- a `/gremlin-recall` command that forces evidence-backed, read-only recall
- a production acceptance runbook
- the agreed post-M7 roadmap

## Configuration contract

The OpenCode client requires:

- `GREMLIN_MCP_URL`: the reachable Streamable HTTP endpoint ending in
  `/mcp`
- `GREMLIN_MCP_API_KEY`: the one-time key for the dedicated OpenCode
  principal
- `OPENCODE_CONFIG=clients/opencode/opencode.json`

Secrets are intentionally absent from committed configuration.

## Boundaries

- No Prime API or persistence behavior changes are required by M7.
- OpenCode remains an external client; Gremlin does not launch or supervise it.
- Gremlin does not gain Docker socket access.
- M7 does not consolidate events or introduce background scheduling.
- M7 does not add memory mutation, OAuth, or broader authorization semantics.
