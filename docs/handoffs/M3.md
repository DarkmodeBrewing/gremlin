# M3 Handoff — Gremlin Chat

## Status

M3 is implemented on `feat/m3-gremlin-chat` and is ready for review.

## Delivered

- A separate `apps/chat` Fastify application serves the browser UI and owns all calls to Gremlin Prime and OpenRouter.
- The browser receives neither the Gremlin principal credential nor the OpenRouter API key.
- Chat requests accept only bounded `user` and `assistant` text history and require the final message to have the `user` role.
- Each browser chat has a stable conversation UUID and a local transcript. Starting a new chat rotates the UUID.
- The user interaction must be archived by Gremlin Prime before OpenRouter is called.
- OpenRouter Chat Completions stream events are parsed with an SSE parser and forwarded as a small browser-facing event protocol.
- Completed assistant output is archived with provider, model, generation, finish, and completion-status metadata.
- If OpenRouter fails after emitting visible text, the partial assistant output is archived with `status: incomplete` where possible.
- User, assistant, and partial-output ingestion failures are explicitly represented in the HTTP or stream response and shown in the UI.
- The cost-bearing chat endpoint is rate-limited and has request, message-count, message-size, and aggregate-content bounds.
- Static responses set a restrictive content security policy and related browser hardening headers.
- Gremlin Chat has a Prime-aware health endpoint and runs as a separate Docker Compose service bound to host loopback by default.

## Chat API contract

`POST /api/chat` accepts:

```json
{
  "conversationId": "019c51d9-d7e6-7e1f-a399-ff70a508b047",
  "messages": [
    {
      "role": "user",
      "content": "Remember that the raw archive is immutable."
    }
  ]
}
```

After the user interaction has been archived, the response uses `text/event-stream` with these events:

| Event | Meaning |
| --- | --- |
| `interaction` | Reports persistence state for a user or assistant turn. |
| `delta` | Carries one assistant text fragment. |
| `complete` | Reports that model streaming finished and whether the full assistant turn was archived. |
| `error` | Reports a model-stream failure and whether visible partial output was archived. |

An ingestion failure before the OpenRouter call returns HTTP 503 and no response stream. Once streaming has begun, later persistence failure is carried inside the stream because the HTTP status has already been committed.

## Configuration

Gremlin Chat requires:

- `GREMLIN_CHAT_API_KEY`
- `OPENROUTER_API_KEY`
- `DEFAULT_CHAT_MODEL`

It also accepts `GREMLIN_PRIME_URL`, `HTTP_HOST`, `HTTP_PORT`, and `LOG_LEVEL`. The Compose service supplies the internal Prime URL and service port.

Provision the required principal with:

```bash
pnpm principal:create client:gremlin-chat
```

Store the generated API key immediately. Prime stores only its hash and cannot recover the plaintext key.

## Boundaries and follow-up

- Gremlin Prime remains the canonical archive. Browser `localStorage` is only the M3 client transcript and session state.
- M3 does not add a Prime conversation-list endpoint or rebuild browser history from the archive.
- M3 does not retrieve memories or inject them into the model context.
- M3 does not include attachments, tools, image generation, voice, model selection UI, multi-user support, or sophisticated conversation organization.
- Gremlin Chat has no application-level user authentication in v0.1. Keep it on loopback or behind a trusted authenticated access layer.

## M4 entry point

M4 should implement the smallest working consolidation slice without changing M3 chat behavior:

1. Select unprocessed interactions as source material.
2. Send bounded source batches through an abstracted consolidation provider.
3. validate structured candidate memories strictly.
4. Persist memories with consolidator identity and complete interaction evidence.
5. Generate and record embeddings through the embedding-provider abstraction.
6. Expose explicit/manual consolidation and make partial or malformed-provider failure visible.

Do not add semantic retrieval or Chat context injection during M4; those begin in M5.
